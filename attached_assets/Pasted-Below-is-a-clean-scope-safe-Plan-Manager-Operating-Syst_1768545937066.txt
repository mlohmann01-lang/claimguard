8.1 Canonical Claim Schema (Conceptual)

8.2 Deterministic Rule Categories (v1)

Rules produce PASS | WARN | FAIL plus reason_code and explain.

Pricing constraints

Unit price <= allowed cap for code (as per ruleset)

Total = qty * unit price checks

Category alignment

Service code belongs to allowed category for plan context

Prevent obvious mismatches

Provider validity

Provider ABN present, basic formatting

Provider existence in tenant directory (or create as “unverified”)

Time & duplication

Service date not in future

Duplicate invoice/line item detection:

same provider + invoice number + date + amount within window

Budget constraints (read-only enforcement)

Warn if category spend velocity indicates overrun

No advice; only “risk flag”

Document completeness

Invoice required fields present: invoice number/date/provider/amount/line items

8.3 Confidence Scoring (v1 simple, deterministic+signals)

Define a claim confidence score 0–100:

Start at 100

Subtract:

-40 for any FAIL

-15 per WARN (cap -45)

-10 if provider unverified

-10 if invoice text extraction uncertain

-20 if duplication risk high

Clamp 0–100

8.4 Decision State Machine (v1)

Based on validation and confidence:

AUTO_READY
Conditions:

No FAIL

Confidence ≥ AUTO_THRESHOLD (default 85, tenant admin can raise but not lower below 80)

Required fields complete
Result:

Show “Auto-Ready” badge + allow “Generate Submission Pack” (still human click)

REVIEW_REQUIRED
Conditions:

Any WARN, or confidence between 60–84
Result:

Show key issues, recommended fields to confirm, require human approval

REJECT_BLOCKED
Conditions:

Any FAIL, or confidence < 60
Result:

Block submission, show failures + fix checklist

Invariant: no claim is ever “auto-submitted” in v1. It becomes “submission-ready pack” requiring human action.
